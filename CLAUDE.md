## What PACT is (read this once, then build it)
Human verification for the AI-agent era. PACT hides a shape in ~600 moving dots: dots **inside** the shape drift
one way, dots **outside** drift the other way. Humans see the shape instantly (motion perception, "common fate").
Any **single frame**, which is exactly what a screenshot-driven AI agent sees, is statistically uniform noise.

1. Pass 3 rounds (pick the hidden shape from 6 icons) → server mints a **120 s, single-use humanity token**.
2. The protected action (booking a seat at a *fictional* high-demand counter, "Tatkal-style") goes through
   **API Gateway → Lambda authorizer → Cedar policies** (`permit` motion-verified, `forbid` replayed tokens).
3. A **Strands Agents red team** on **Amazon Bedrock** (Nova/Claude; plus local **Ollama**) attacks the same puzzle
   live in the **Lab** page; a scoreboard shows **human vs AI pass rates with 95% CIs**.
4. Accessible, non-cognitive path: **Cognito-verified account → token (assurance=account) → Cedar daily quota**
   (WCAG 2.2 SC 3.3.8).
5. Build It track: same code runs on localhost via **SAM CLI + DynamoDB Local/LocalStack + Ollama + Cedar**.

## Non-negotiable rules
### Hackathon rules (breaking one = disqualified or zero)
1. Only work created during the event. Never import code from older projects. Open-source libs are fine; credit
   them in README › Credits with their licence.
2. AWS must be used **and visibly shown in the video**. The writeup alone is not enough.
3. Every AI coding tool used must be listed in the writeup (`docs/SUBMISSION.md › AI tools used`).
4. Repo public at submission; video on YouTube, under 3:00; one submission per team, before the deadline.
### Engineering rules
5. `main` is always demo-able. Small commits. Never end a phase with `main` broken.
6. No secrets in code, git, logs or chat. Cloud token key = Secrets Manager (auto-generated by the template);
   local = the dummy value in `backend/env.local.json`. Log a token's `jti`, never the token.
7. Puzzle answers, seeds and specs never leave the server; only `generate_challenge()["public"]` is sent.
8. Generator randomness = `KeyedRng` (SHAKE-256) only. Never `random.Random` in `pact_core`
   (Mersenne Twister state is recoverable from the published dots and would leak the hidden mask).
9. DynamoDB expressions always use `ExpressionAttributeNames` (`#s`, `#ttl`, …): STATUS and TTL are reserved words.
10. Never call Bedrock synchronously from an API route (HTTP API integration timeout is 30 s). Agent runs are async.
11. Never set `ReservedConcurrentExecutions` (new accounts have a concurrency limit of 10, so the deploy fails).
12. No destructive AWS operations (delete-stack, delete-table, `s3 rb`, IAM edits) without explicit human approval.
13. Be truthful: a check "passes" only if you ran it and saw it pass. Never invent or round up evaluation numbers.
    Infra errors are not "agent failures". Label every cohort honestly.
14. Use a fictional brand in the UI. Never use IRCTC or any real organisation's name or logo in the product UI
    (real organisations may be cited as *context* in the README and writeup only).

## Session protocol (every session, every time)
1. Read `MEMORY.md` (a SessionStart hook re-injects Snapshot / Next Steps / Open Issues automatically).
2. Open the current phase file in `docs/phases/` and read the docs it lists under **Read first**.
3. Per task: implement → verify (`docs/TESTING.md`) → commit → update `MEMORY.md` (Log + Snapshot + Next Steps).
4. On any error: `docs/SELF_CORRECTION.md` (reproduce → root cause → minimal fix → verify → log; max 3 attempts,
   then take the documented fallback or escalate with a precise question).
5. A Stop hook blocks ending a turn once if files changed after `MEMORY.md` was last updated. Update it; don't fight it.
6. Blocked on something only a human can do? Add it to `MEMORY.md › Human-Blocked`, tell the human the exact
   step from `docs/HUMAN_STEPS.md`, and continue with unblocked work.

## Conventions
- Python 3.12, ruff (line 120), type hints, pytest + moto. Handlers stay thin; logic lives in `pact_core`.
  Logs: `logging` + `extra={...}` (Lambda JSON log format is on), one event name per line.
- TypeScript strict; React function components; Tailwind tokens from `src/index.css`; keep components under ~200 lines.
- Names, routes, env vars, headers, table keys: **exactly** as in `docs/ARCHITECTURE.md › Naming registry`.
- Commits: Conventional Commits (`feat(api): …`, `fix(web): …`, `docs: …`). Tag `phase-N-done` at phase end.
- Region `us-east-1`, stack `pact-dev`, Python Lambdas on arm64.
- New dependency or deviation from these docs → one line in `MEMORY.md › Decisions` (what, why, alternatives).
