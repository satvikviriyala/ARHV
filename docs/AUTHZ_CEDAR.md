# AUTHZ — humanity tokens, the Lambda authorizer, and Cedar

Reference (tested): `pact_core/tokens.py`, `functions/authorizer/authz.py`, `functions/authorizer/cedar/*`,
`backend/tests/test_authz.py` (in `docs/reference/scaffold/`). Offline demo: `make cedar-demo`.

## 1. Humanity token
- HS256 JWT (PyJWT). Key: 64 random alphanumerics generated by CloudFormation into Secrets Manager
  (`pact/dev/token-signing-key`); never leaves AWS; Lambdas fetch it once per container.
- Claims: `iss="pact"`, `aud="pact-demo"`, `sub` (motion: `v_<16 hex>`; account: Cognito `sub`), `jti` (uuid4 hex),
  `iat`, `nbf=iat-1`, `exp=iat+120`, `asr` (`motion`|`account`), `cid` (motion only).
- Verification requires `exp, iat, jti, sub, asr`, checks signature, `iss`, `aud`, 5 s leeway, and `asr` ∈ levels.
- **Single use:** the authorizer does `PutItem JTI#<jti>` with `attribute_not_exists(PK)`; a second use sets
  `tokenReplayed=true` and Cedar's `forbid-token-replay` denies it.
- Client keeps the token **in memory only** (not localStorage), sends it as `x-pact-token`.

## 2. Where decisions happen
`POST /v1/demo/bookings` has `Auth: Authorizer: PactTokenAuthorizer`, a **Lambda authorizer** (payload 2.0, simple
responses, identity source `$request.header.x-pact-token`, **`ReauthorizeEvery: 0`, so no caching**. Caching a
decision would let a single-use token be reused).
- Header missing → API Gateway returns **401** without invoking the authorizer.
- Authorizer returns `isAuthorized: false` → API Gateway returns **403** `{"message":"Forbidden"}`.
- Authorizer throws or times out → **500**. That's why the handler catches everything and denies (fail closed).

Authorizer steps: verify JWT → mark `jti` → read today's quota (account only) → `authz.decide()` → log
`authz_decision` → `{"isAuthorized": …, "context": {sub, assurance, jti, decision, policies}}`. The context reaches
BookingFunction as `event.requestContext.authorizer.lambda`.

## 3. Cedar (the policies are the product's security logic; keep them short and readable)
`cedar/schema.cedarschema`
```cedar
namespace Pact {
  entity Visitor = { assurance: String };        // "motion" | "account" (from the verified token)
  entity Counter = { kind: String };             // the protected resource (fictional booking counter)
  action "BookTicket" appliesTo {
    principal: [Visitor], resource: [Counter],
    context: { tokenReplayed: Bool, bookingsToday: Long },
  };
}
```
`cedar/policies.cedar`
```cedar
@id("permit-motion-book")
permit (principal is Pact::Visitor, action == Pact::Action::"BookTicket", resource is Pact::Counter)
when { principal.assurance == "motion" };

@id("permit-account-book-with-quota")
permit (principal is Pact::Visitor, action == Pact::Action::"BookTicket", resource is Pact::Counter)
when { principal.assurance == "account" && context.bookingsToday < 2 };

@id("forbid-token-replay")
forbid (principal, action, resource) when { context.tokenReplayed };
```
Semantics: default deny; any matching `forbid` overrides all `permit`s. The quota literal `2` must equal
`config.ACCOUNT_DAILY_QUOTA` (a test asserts this).

`authz.decide(sub, assurance, action, token_replayed, bookings_today)`:
- Builds entities (`Pact::Visitor{assurance}`, `Pact::Counter{kind:"high_demand"}` id `rush-hour-counter`).
- Uses the **dict form** for principal/action/resource (`{"type": "Pact::Visitor", "id": sub}`), so a hostile `sub`
  can't break Cedar string parsing (a quote in an id broke the string form in testing).
- Validates against the schema, maps Cedar's positional ids (`policy0`…) to `@id` annotations via
  `cedarpy.policies_to_json_str`, and returns `{"decision": "ALLOW"|"DENY", "policies": [...], "errors": [...]}`.

## 4. Decision table (tested; `make cedar-demo` prints it)
| Scenario | assurance | replayed | bookingsToday | Decision | Policy |
|---|---|---|---|---|---|
| Passed motion challenge | motion | false | 0 | **ALLOW** | permit-motion-book |
| Same token again | motion | true | 0 | DENY | forbid-token-replay |
| Verified account | account | false | 0 or 1 | **ALLOW** | permit-account-book-with-quota |
| Account over quota | account | false | 2 | DENY | (default deny) |
| Anything else | other | – | – | DENY | (default deny) |

## 5. Explain route (for the video and for debugging 403s)
`POST /v1/authz/explain {"token": …}` runs the same verification + Cedar decision **without** marking the `jti`, and
returns the decision and matched policies. The frontend Dev Panel calls it after a booking (expect
`forbid-token-replay`, since the token was just used) and when a booking returns 403.
